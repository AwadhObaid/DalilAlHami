Phase 17A.2 contact-cache recovery
==================================
Runtime QA found an upgrade-only compatibility case:
an older client could advance last_sync_version after the backend began
returning business_contact_numbers, even though that old client ignored the
new nested field. When Schema 11 was later installed, contact_numbers_json was
empty but the sync cursor was already current, so no backfill was requested.

SQLite Schema 12 fixes this once:
- Schema < 11 still adds contact_numbers_json.
- Schema < 12 resets only the directory last_sync_version to 0 and clears
  last_synced_at.
- The next normal sync requests one full directory snapshot and backfills
  contact numbers.
- Account cache, sync queue, user state and Supabase are not reset.
